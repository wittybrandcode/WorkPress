# WorkPress — وثيقة متطلبات المنتج v2

## الرؤية

WorkPress هو **Organizational Memory Engine** مبني فوق WordPress. الأشخاص ينشئون العمل، والعمل يولّد المعرفة، والمعرفة تتراكم كذاكرة مؤسسية. إدارة المشاريع هي أول تطبيق لهذه المحرك، وليست تعريف المنتج أو حدّه.

المرجع الأعلى لكل قرار منتج أو تصميم أو تنفيذ هو [FIRST_PRINCIPLES.md](FIRST_PRINCIPLES.md). المنتج ليس بديلًا لـ WordPress أو لنظام صلاحياته، وليس مدير مهام خاصًا بمجال واحد.

## مبادئ المنتج

- Projects هي سياق عمل وتمثل taxonomy؛ Tasks هي posts؛ Contributions هي comments؛ الأشخاص هم WP users.
- WordPress يملك المصادقة وcapabilities؛ WorkPress يملك العضوية والتكليف وسجل العمل.
- الحالة الحالية مختلفة عن التاريخ: الأولى meta، والثاني contributions.
- Core لا يعرف المجال التجاري؛ CoWorkPress يملك التجربة؛ Office Packs تملك التخصص؛ Modules تضيف قدرات اختيارية.
- لا جداول مخصصة كمصدر حقيقة ولا Knowledge post مستقل. يجوز مستقبلًا استخدام Index Tables اختيارية قابلة لإعادة البناء كـ read models للأداء فقط.
- Project Templates مفهوم من Core يبدأ به العمل؛ Office Packs تقدم قوالب المجال وتفسيره.
- Workflow في Core يعرّف states والانتقالات المسموح بها فقط؛ المعنى التجاري لتلك الانتقالات ليس من مسؤولية Core.

## المستخدمون والنتائج

| مستخدم | يحتاج إلى | النتيجة |
| --- | --- | --- |
| **المدير العام** | حوكمة النظام، مصفوفة الصلاحيات، إنشاء المشاريع، واعتماد الحلول | حوكمة شاملة ومساحة عمل آمنة وسجل قرارات غير قابل للمحو |
| **قائد / عضو الفريق الفني** | رؤية مشاريعه، تنفيذ مهامه، إدارة الكانبان، وإضافة المساهمات الفنية | مسؤولية واضحة وتاريخ عمل منسوب لصاحبه |
| **مستفيد / صاحب طلب (Portal)** | تقديم طلبات العمل، متابعة المخرجات، تقديم الاستفسارات، ومصادقة الاستلام | مشاركة منضبطة ومعزولة عبر بوابة المستفيدين دون صلاحيات زائدة |
| **مشترك / متابع عادي (Site)** | تصفح مقالات الموقع العام، التعليق، والشراء | تجربة ووردبريس طبيعية دون تداخل مع غرفة العمليات أو البوابة |
| **عضو المؤسسة** | البحث في المعرفة المسموح بها والمستخلصة من الحلول المعتمدة | إعادة استخدام حلول موثوقة وموثقة تاريخياً |
| **مطور امتداد** | تطوير Office Pack أو Module تخصصي | تخصيص كامل لمجال العمل بلا تعديل في النواة |

## قصص المستخدم الأساسية

1. كمدير، أنشئ مشروعًا وأضيف أعضاءً بأدوار محلية؛ فلا يظهر إلا لهم.
2. كمدير أو مستخدم مخول، أنشئ مهمة بتفاصيل Gutenberg ووسائط وموعد وأولوية، وأكلف عضوًا؛ فيسجل النظام التكليف كحالة حالية وContribution تاريخية.
3. كعضو، أضيف تنفيذًا أو تقدّمًا أو مراجعة أو قرارًا كمساهمة typed مع مرفقات؛ ويبقى قابلًا للتتبع.
4. كمدير، أعتمد مساهمة واحدة أو أكثر؛ فتدخل نتائجها قاعدة المعرفة عند إغلاق المهمة دون أن يعني الاعتماد الإغلاق تلقائيًا.
5. كمستخدم مخول، أغلق أو أعيد فتح المهمة؛ فيحفظ الحدث ويُطبّق قفل المساهمات عند الإغلاق.
6. كعضو، أبحث في المهام المغلقة والمساهمات المعتمدة ضمن المشاريع التي أملك حق رؤيتها.

## قواعد القبول

- الرؤية تتبع العضوية افتراضيًا؛ صلاحية عامة وحدها لا تكشف مشروعًا خاصًا إلا في مسار إداري صريح.
- التعديل يتطلب capability وعضوية ودور مشروع مناسب، وقد يتطلب التكليف بحسب الإجراء.
- كل تغيير assignment أو state أو acceptance أو close/reopen يترك Contribution.
- يمكن اعتماد مساهمات عديدة؛ المساهمة المعتمدة مرجع معرفة وليست بالضرورة «حلًا وحيدًا».
- لا تقبل المهمة مساهمات بعد close، وتقبلها بعد reopen المخول.
- واجهة CoWorkPress لا تتجاوز API ولا تقرر الحقوق؛ Core يعيد التحقق دائمًا.

## النطاق

### MVP

Project، Membership، project roles، Task، assignment، timeline/contributions، acceptance، close/reopen، knowledge، REST API وواجهة CoWorkPress عامة (قائمة/لوحة/تفاصيل/معرفة).

### خارج MVP

منطق قطاعات الأعمال، Gantt، تتبع الوقت، إشعارات معقدة، تقارير متخصصة وAI. تنفذ لاحقًا كـ Modules أو Office Packs.

## غير وظيفية

- WordPress 6.0+ وPHP 7.4–8.3+، مع التحقق من توافق أدوات البناء الفعلية.
- مصادقة WordPress أصلية، تعقيم وتحقق schemas، وREST authorization على كل route.
- هدف الأداء: أقل من 150ms لطلبات MVP الأساسية في بيئة الاختبار؛ pagination عند القوائم.
- حفظ المراجعات والوسائط ومحرك البحث الأصليين، مع قابلية وصول واستجابة مناسبة للواجهة.
